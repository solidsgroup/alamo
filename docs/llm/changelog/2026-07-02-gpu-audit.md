## The live defect

`DeviceErrorFlag::value()` (`src/Util/Util.H:68-78`) → AMReX
`DeviceScalar::dataValue()` → `Device::streamSynchronize()`, which syncs only
the **current** CUDA stream. `MFIter` cycles boxes across a **pool** of
streams — the same mechanism behind the historical `interpolation()` `tmpfab`
use-after-free (`benchmark/archive/elixir_race_audit.md`). So a
`SetDeviceError` write from an earlier-streamed box can still be in flight
when `AbortIfDeviceError` reads the flag right after the MFIter loop
(`Newton.H:121-124,228-231` — unconditionally compiled, always live in
production; `Elastic.cpp:675,889` — `AMREX_DEBUG`-gated). Writes are atomic,
so there's no corruption; the failure mode is a **silent false negative** — a
NaN/invalid-`kinvar` error on a non-last-streamed box goes undetected on
multi-box runs. Single-box smoke tests can't exhibit it, which is why
`tests/GPU/` (9/9 green) hasn't caught it.

**Fix:** `amrex::Gpu::streamSynchronizeAll()` before the
flag read, cleanest inside `Util::AbortIfDeviceError` (`Util.H:148-151`) so
all four call sites are covered by one edit — the same idiom already used for
the `dsol_mf` UAF fix at `Newton.H:459`. Cost is one full-device sync per
Newton iteration — negligible. Follow-up crash closure also added the same sync idiom at the broader
`Base::Mechanics::TimeStepBegin` elastic operator lifetime boundary, before the
local `elastic_op` destructor can free AMR/MG-level buffers while a straggler
kernel is still in flight.

## The CI gap

`.github/workflows/chamber-gpu-correctness.yml`'s `golden-gpu` and
`phase1-budget-gate` jobs are gated on a `has-cuda-runner` repo topic that is
not wired to any runner — only `golden-cpu` actually executes. The workflow
reports green with zero GPU signal, and does so silently (not even a visible
"skipped: no GPU"). Tracked as `GPU_ROADMAP_V3.md` task **4.H**.

## Supporting evidence for the Fapply kernel win (task 3.A)

Reading `Operator::Elastic::Fapply` directly confirms the C1 branch
(`chamber-gpu-elastic-opt`) is targeting the right hotspot: grad(C)
(`Elastic.cpp:615-624`) builds three live `Set::Matrix4` temporaries (63
doubles) per cell, and the `if (!m_uniform)` guard around it never actually
skips the branch for chamber sims — `Mechanics.H:198` forces
`SetUniform(false)` unconditionally, so it's always live, not a rare path.
Two adjacent, not-yet-staged opportunities found: `DDW(i,j,k)` is loaded from
global memory twice per cell (`:613` and `:629`) when psi is active, and the
in-kernel boundary branch (`:537-670`) is the fuller motivation for the
already-planned task 3.B (interior/boundary kernel split), beyond what the
C1 `sig`-sink edit partially addresses.

## Dormant landmines (inert today, recorded so no one rediscovers them via a NOVA crash)

Not in the current `flame`-only GPU closure, so no action required unless the
closure is extended:

1. `PhaseFieldMicrostructure::Integrate` (`PhaseFieldMicrostructure.cpp:449-483`)
   accumulates host members via `+=` inside a device lambda's implicit `this`
   capture — the exact pre-fix pattern behind the 2026-06-26
   `Base::Mechanics::Integrate` CUDA-700 crash (see
   `changelog/2026-06-26-3d-elastic-gpu-fix.md`). Fix recipe: port the
   `ReduceOps` pattern first if this integrator is ever added to
   `ALAMO_GPU_SUPPORTED_INTEGRATORS`.
2. Every solid model except `Finite::NeoHookean`/`NeoHookeanPredeformed`
   lacks `AMREX_GPU_HOST_DEVICE` on `W`/`DW`/`DDW`. Static name-hiding
   dispatch (`Solid.H:40-43`) means an un-annotated override silently shadows
   the annotated base rather than failing loudly.
3. `Operator/Diagonal.cpp` has no device-safety concept at all (raw host
   loops); not part of the GPU closure (`Elastic::Diagonal` in `Elastic.cpp`
   is the one actually used on device).
